# TC-002: Link and discriminate finite protocol structure

## Description

Verify FR-288 static identity, FR-287 runtime identity, FR-217 role
classification and FR-262 relationship consistency across every finite
protocol, communication and control subject.

## Test Procedure

Admit the published version-2 protocol handoff and an independently selected
version-1 static binding definition carrying exact role classifications and
slot-to-producer-kind/correspondence facts. Bind two concurrent workflow
instances through imported Observation `QualifiedSubject` values. Bind exact
runtime subjects for every required workflow, role-instance, participant,
component, endpoint, message, send, receive, delivery, attempt and effect slot;
bind one participant compatibly to two distinct role instances; and classify
every static role once as exact `internal` or `external`.

Mutate each FR-288 source-document, declaration-handle, formal-owner/clause,
language, profile, model, accepted static binding definition and each required
correspondence component independently.
For one unchanged FR-288 key, alter every typed declaration-content family:
scope, anchor, binder, value, activation, role, relationship, channel, FIFO
binder/key/type/dependency, compensation, temporal requirement, control, edge,
guard, constraint, event, await interval/branch, run and finish. Separately
change only external path, locus, build provenance, runtime observation and
resource ceiling.

For runtime bindings, omit, duplicate and add a subject; substitute every wrong
FR-287 kind; change each authority and producer-local identity component; reuse
a static slot identity; reuse one subject with incompatible binding facts; omit
internality and offer `Internal`, `external ` and another unknown spelling.
Mutate the independently selected slot compatibility, then offer a producer
kind compatible only by equal spelling and a valid producer-local kind whose
spelling differs from the QSL binding kind. Submit an absent, older and unknown
static/runtime binding-contract version and a version-1 compiled artifact.
Replay one exact FR-262 relationship, reuse its key with
conflicting declaration or endpoints, supply two distinct relationship keys for
one slot, and supply two distinct keys for two distinct slots.

For FIFO, compare the same exact typed evaluated value on the same channel, two
different values on that channel, and the same value on two channels. Also
exercise unordered and all inclusive delivery-cardinality boundaries. Generate
every permitted branch interleaving and retain the existing compiler-owned
adverse corpus for invalid references, joins, cycles, termination, channel
shape and choices without reimplementing those admission rules.

## Expected Results

Valid structures link with exact distinct static and runtime identities, exact
five-component channel premises and complete typed semantic content. The same
FIFO channel and value form one partition, while either changed component forms
a different partition and adds no causal edge. Exact relationship replay is
idempotent, two keys for one slot are ambiguous, and two keys for two slots
remain distinct. Old or unknown contract/artifact versions are unsupported.
Changing only a concrete runtime subject or relationship leaves FR-288
unchanged, while changing the accepted static binding selection changes it.
Each invalid consumer-owned mutation returns the exact affected coordinate and
any real originating locus with no linked representation, and
each compiler-owned adverse case remains refused before linking. Every authored
semantic change requires another FR-288, while external presentation changes do
not independently change the key or graph.
